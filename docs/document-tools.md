# 文档工具设计与使用

## 从用户意图出发

“把旧名称统一成新名称”不应让模型重写全文；“只改第二处”不应影响第一处；“哪里还没写完”不应自动删除正文。因此工具分为确定性的本机操作、只读模型工具、最终编辑方案三层，而不是为每个提示词创造一个假工具。

| 入口 / 工具           | 行为                                                             | 写入边界                       |
| --------------------- | ---------------------------------------------------------------- | ------------------------------ |
| 本机查找              | 精确子串查找、匹配数量、分页、跳转段落                           | 不发送模型请求，不写正文       |
| 本机替换预览          | 根据已显示快照和准确总数生成方案                                 | 始终待审阅，点击应用才写入     |
| `inspect_document`    | 段落/字符/标题统计；规则检查标题跳级、空标题、占位内容、重复段落 | 只读，不验证事实或引用         |
| `search_document`     | 返回总匹配数、段落 ID、段内序号、片段和 `nextOffset`             | 只读，不是联网搜索             |
| `replace_in_document` | 将明确的统一替换编译为精确操作                                   | 一个最终方案，不直接应用       |
| `edit_document`       | 原有编辑操作加 `replace_text`                                    | 沿用版本、原文、范围校验和撤回 |

AI 写作入口有校对润色、精简、中译英、摘要、逻辑审阅、提取待办、整理表格和术语一致性。它们只填入可编辑提示词，并选择合适的 Agent / Ask 模式，不自动发起请求。缺失的负责人、日期和数据必须明确标注，不能由模型补造。

## 精确替换契约

`replace_text` 需要 `paragraphId`、完整 `expectedText`、`find`、`text` 和 `expectedMatches`。匹配区分大小写，按不重叠字面子串计算，不支持正则、完整单词模式或跨段替换。`expectedMatches` 始终是整个原始段落中的总匹配数；可选 `occurrence` 从 1 开始，只修改该次出现。

浏览器在一个 ProseMirror 事务内从后向前替换；未涉及的文本、链接和样式保留。新文字继承匹配起点的文本样式，不承诺保留被替换短语内部的多种混合样式。含硬换行或其他非文本行内节点的浏览器段落受保护，避免文本偏移与实际节点位置不一致。

Word 先批量获取搜索 Range，核对数量与每个 Range 的原文，然后才排队写入。`^` 需要转义，禁用通配符和忽略空格/标点等宽松匹配选项。Word 多操作写入不是数据库事务；同步失败仍可能部分执行，必须使用 Word 原生撤销检查恢复。

查找文本上限 120 字符；替换文本上限 2,000 字符且不含控制字符/换行；单段结果不超过 30,000 字符；一批最多 60 个段落、1,000 处替换。范围内存在受保护匹配时整批拒绝，不静默跳过。只限定部分段落时，总数必须对应该范围。

## 只读工具循环与隐私

全文 Agent 一轮最多四次只读工具调用，之后只能返回答案或一个最终编辑方案，最多五次模型请求。整个回合共用 180 秒期限和 500,000 字符模型输出预算；单个工具结果上限 32,000 字符、累计 96,000 字符。读取结果通过匹配的 `tool_call_id` 回传，不伪造写入成功。重复/缺失只读调用 ID、未知工具、参数错误、截断或取消都会中止。

Ask 保留无工具的文本问答协议；选区模式只暴露 `replace_selection`，服务端也拒绝越界的全文工具。选区不发送当前全文段落，但现有对话历史仍随请求发送；此前会话中的内容不因此自动消失。模型工具产生的结果会随已授权的对话发给所选服务商，本机界面查找和替换预览则不调用模型。读取和工具结果中的文档内容始终是数据，不是系统指令。

## 官方技术依据

- [Microsoft：Word search options](https://learn.microsoft.com/en-us/office/dev/add-ins/word/search-option-guidance)：搜索范围、匹配选项和 `^^` 字面 caret 转义。
- [Microsoft：correlated objects / split loop](https://learn.microsoft.com/en-us/office/dev/add-ins/concepts/correlated-objects-pattern)：先批量加载，再处理数据，避免每个匹配调用一次 `context.sync()`。
- [OpenAI：function calling](https://developers.openai.com/api/docs/guides/function-calling)：工具调用是需要执行和回传结果的多步流程；本实现保留现有 Chat Completions 协议，不迁移供应商接口。

## 验证边界

自动化覆盖真实 ProseMirror、React/jsdom 工具面板、协议和纯函数、模拟模型 SSE，以及模拟 Office 主机。原生 Word/WebView2 的字体渲染、混合样式搜索、受保护文档和多人协作仍需实机验收。未增加联网检索、自动引文验证、付费服务依赖或任何任意代码执行工具。
